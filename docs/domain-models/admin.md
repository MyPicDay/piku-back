# Admin 도메인 모델

- Status: Active
- Audience: Engineers
- Source of Truth: Yes
- Last Reviewed: 2026-07-11

## 도메인 개요

Admin 도메인은 **일반 사용자와 분리된 운영자 계정, 관리자 인증, 관리자 세션, 감사 로그, 운영 통계 정책을 관리**하는 도메인입니다. 관리자 계정은 서비스 사용자 계정과 별도 계정 체계와 식별자를 사용하며, 관리자 운영 기능의 접근 주체를 정의합니다.

### 목적

- 일반 사용자 인증과 분리된 관리자 전용 인증 체계를 제공한다.
- 관리자 계정의 생성, 최초 설정, 등급 변경, 비활성화, 잠금 해제, OTP 초기화 등 운영 행위를 일관된 규칙으로 관리한다.
- 관리자 세션, CSRF, 인증 버전, 단일 활성 세션 정책을 통해 관리자 인증을 보호한다.
- 관리자 작업 감사 로그와 운영 통계 조회 정책을 통해 운영 추적성과 서비스 현황 조회를 지원한다.

### 핵심 책임

- 관리자 계정 생성 및 임시 자격 증명 발급
- 최초 로그인, 정식 로그인 자격 증명 설정, OTP 등록과 인증
- 관리자 등급 기반 접근 제한
- 패스워드 실패 잠금, OTP 실패 차단, 계정 비활성화와 재활성화
- 관리자 사전 세션 단계 진행, 인증 세션 발급, 보안 변경 시 세션 폐기
- 관리자 작업 감사 로그 기록과 조회
- 관리자 통계 이벤트 기록, 종료된 날짜의 일별 집계, 당일 실시간 통계 조회

### 도메인 경계

- **Aggregate Root**: `AdminAccount`
- `AdminEmail`, `AdminLoginId`, `AdminId`는 관리자 계정의 식별과 입력 정합성을 담당하는 값 객체다.
- `AdminSession`은 관리자 인증 단계, 자격 증명 해시, 수명과 폐기 상태를 관리한다.
- `AdminAuditLog`, `AdminStatisticsEvent`, `AdminDailyStatistics`는 관리자 운영 추적과 조회용 통계 데이터를 표현한다.
- 관리자 쿠키, CSRF, Origin과 보안 필터 동작은 Admin 모델의 책임이 아니다. 일반 사용자용 인증 정보는 관리자 인증 수단으로 사용하지 않는다.
- `AdminStatisticsEvent`와 `AdminDailyStatistics`는 운영 지표의 정의와 집계 결과를 소유하지만, 지표를 구성하는 원천 업무 사실의 소유권까지 가져오지 않는다.

### 관리자 접근 정책

- 관리자 계정 생성, 등급 변경, 비활성화, 재활성화, 잠금 해제, 임시 패스워드 재발급, OTP 초기화, 이메일 변경, 감사 로그 조회는 `SUPER_ADMIN`만 수행할 수 있다.
- 통계 조회는 모든 관리자 등급이 수행할 수 있다.
- 통계 CSV 내보내기는 `SUPER_ADMIN`과 `OPERATOR`만 수행할 수 있다.
- 관리자 UUID는 `SUPER_ADMIN`의 목록과 상세 조회에서만 표시하며 상세 조회 식별값으로 사용한다.
- 관리자 이메일과 로그인 아이디는 인증, 온보딩, 생성, 임시 패스워드 재발급 응답에 포함하지 않는다.
- `SUPER_ADMIN`의 관리자 목록과 상세 조회에서만 이메일과 로그인 아이디를 마스킹해 표시한다.
- 감사 로그에는 이메일 값을 저장하지 않는다. 과거 형식의 데이터가 조회되더라도 응답에서는 이메일을 마스킹한다.

## 관리자 등급(AdminRole)

_Enum_

### 상수

- `SUPER_ADMIN` : 관리자 계정과 관리자 권한을 관리하는 최상위 등급
- `OPERATOR` : 서비스 운영과 통계 확인을 수행하는 운영 등급
- `VIEWER` : 통계와 현황을 조회하는 읽기 중심 등급

### 규칙

- 관리자는 하나의 등급만 가진다.
- 마지막 남은 `SUPER_ADMIN`은 비활성화하거나 등급을 낮출 수 없다.
- 관리자는 자기 계정의 등급을 직접 변경할 수 없다.
- 등급 변경 사유 입력은 1차 범위에서 요구하지 않지만, 변경 전후 등급은 감사 로그에 기록한다.

## 관리자 계정 상태(AdminAccountStatus)

_Enum_

### 상수

- `ACTIVE` : 로그인 가능한 기본 상태
- `LOCKED` : 패스워드 실패 누적으로 일시 잠긴 상태
- `INACTIVE` : `SUPER_ADMIN`이 사용 중지한 상태

### 규칙

- 최초 설정이 완료되지 않은 관리자도 계정 상태는 `ACTIVE`일 수 있다. 이 경우 설정 단계 외 관리자 페이지 접근은 제한한다.
- `LOCKED` 상태는 자동 해제 시각이 지나거나 `SUPER_ADMIN`이 수동 해제하면 해제된다.
- `INACTIVE` 상태에서는 로그인과 보호된 관리자 기능 접근을 모두 거부한다.
- 계정 비활성화 사유는 반드시 입력한다.

## 관리자 계정(AdminAccount)

_Entity, Aggregate Root_

### 속성

- `id` : 관리자 내부 식별자. UUID v7 형식을 사용한다.
- `email` : 임시 로그인 아이디이자 관리자 연락용 이메일이다.
- `loginId` : 최초 설정 후 사용하는 정식 로그인 아이디다.
- `nickname` : 운영 화면에 표시되는 관리자 닉네임이다.
- `role` : 관리자 등급이다.
- `status` : 관리자 계정 상태다.
- `passwordHash` : 정식 패스워드 해시다.
- `temporaryPasswordHash` : 임시 패스워드 해시다.
- `temporaryCredentialExpiresAt` : 임시 로그인 정보 만료 시각이다.
- `otpSecret` : 등록 완료된 OTP 비밀키의 보호된 값이다.
- `pendingOtpSecret` : OTP 등록 과정에서 검증 전까지 보관하는 보호된 값이다.
- `loginFailureCount` : 마지막 로그인 성공 이후 누적된 패스워드 실패 횟수다.
- `otpFailureCount` : OTP 인증 실패 횟수다.
- `lockedUntil` : 자동 잠금 해제 기준 시각이다.
- `otpBlockedUntil` : OTP 인증 차단 해제 기준 시각이다.
- `authenticationVersion` : 기존 관리자 인증을 즉시 무효화하기 위한 단조 증가 버전이다.

### 행위

- 관리자 초대와 임시 자격 증명 발급
- 정식 로그인 아이디와 패스워드의 원자적 설정 및 임시 패스워드 무효화
- OTP 등록 시작과 완료
- 패스워드 실패 기록과 계정 잠금
- OTP 실패 기록과 OTP 인증 차단
- 로그인 성공 기록과 실패 횟수 초기화
- 등급 변경, 비활성화, 재활성화, 잠금 해제
- 인증 버전 증가

### 규칙

- 관리자 이메일은 관리자 계정 간 중복될 수 없다.
- 관리자 이메일은 일반 사용자 이메일과 중복될 수 있다.
- 임시 로그인 아이디는 관리자 이메일을 사용한다.
- 임시 패스워드 원문은 생성 화면에서 한 번만 표시하며 저장하지 않는다.
- 임시 로그인 정보는 발급 후 24시간 동안만 유효하다.
- 정식 로그인 아이디와 정식 패스워드는 하나의 원자적 온보딩 행위로 함께 설정한다.
- 로그인 아이디 중복이나 패스워드 정책 검증이 실패하면 두 값 모두 변경하지 않는다.
- 정식 로그인 아이디 설정 이후에는 이메일 로그인을 허용하지 않는다.
- 정식 로그인 아이디는 설정 이후 변경하지 않는다.
- 패스워드 로그인 실패가 5회 누적되면 계정을 잠근다.
- OTP 실패가 5회 누적되면 10분 동안 OTP 인증을 차단한다.
- 실패 횟수, 잠금, OTP 차단 상태는 관리자 예외가 발생해도 저장되어야 한다.
- 로그아웃, 패스워드 변경, 등급 변경, 비활성화, OTP 초기화처럼 기존 인증을 무효화하는 행위는 인증 버전을 증가시킨다.

### 정식 로그인 아이디 정책

- 정식 로그인 아이디는 필수이며 앞뒤 공백을 제거한 값을 검증하고 저장한다.
- 길이는 4자 이상 15자 이하여야 한다.
- 영문 소문자, 숫자, 밑줄, 하이픈만 사용할 수 있다.
- 영문 대문자, 공백, 한글과 그 밖의 특수문자는 사용할 수 없다.
- 관리자 계정 간 중복될 수 없다.
- 최초 온보딩에서 한 번만 설정할 수 있으며 설정 이후 변경할 수 없다.
- 정식 로그인 아이디 설정 전에는 이메일과 임시 패스워드로만 임시 로그인할 수 있다.
- 정식 로그인 아이디 설정 후에는 이메일을 정식 로그인 아이디로 사용할 수 없다.
- 예약어 제한은 1차 범위에서 적용하지 않는다.

### 정식 패스워드 정책

- 정식 패스워드는 8자 이상 20자 이하여야 한다.
- 영문 대문자, 영문 소문자, 숫자, 특수문자를 각각 하나 이상 포함해야 한다.
- 공백을 포함할 수 없으며 ASCII 범위의 문자만 사용할 수 있다.
- 정식 로그인 아이디와 동일하거나 정식 로그인 아이디 문자열을 포함할 수 없다.
- 최초 온보딩의 자격 증명 설정과 인증 완료 후 패스워드 변경에 동일한 패스워드 정책을 적용한다.
- 정식 패스워드는 로그인 아이디와 패스워드의 최초 통합 설정이 완료된 계정에서만 변경할 수 있다.
- 패스워드 원문은 저장하지 않고 단방향 해시만 저장한다.
- 정식 패스워드를 설정하면 임시 패스워드와 임시 자격 증명 만료 정보는 즉시 무효화한다.
- 패스워드 변경에 성공하면 기존 활성 관리자 세션을 모두 폐기한다.

## 관리자 세션(AdminSession)

_Entity_

### 속성

- `id` : 관리자 세션 식별자
- `adminId` : 세션을 소유한 관리자 식별자. 익명 사전 세션에서는 비어 있다.
- `phase` : 익명, 온보딩 단계, 로그인 OTP 단계, 인증 완료 중 현재 단계
- `sessionTokenHash` : 브라우저 세션 자격 증명 원문의 해시
- `csrfTokenHash` : CSRF 자격 증명 원문의 해시
- `authenticationVersion` : 세션에 고정된 관리자 인증 버전
- `absoluteExpiresAt` : 세션 절대 만료 시각
- `idleExpiresAt` : 마지막 활동 기준 유휴 만료 시각
- `lastActivityAt` : 마지막 유효 요청 시각
- `status` : 세션 상태
- `revokedAt` : 세션 만료 또는 폐기 시각

### 행위

- 익명 사전 세션 시작
- 관리자 계정과 사전 세션 결합
- 온보딩과 로그인 단계 전이
- OTP 성공 시 인증 완료 세션 승격과 세션·CSRF 자격 증명 교체
- 마지막 활동과 유휴 만료 갱신
- 세션 만료
- 세션 폐기

### 규칙

- 관리자 계정은 하나의 활성 인증 완료 세션만 유지한다.
- 새 OTP 인증에 성공하면 기존 인증 완료 세션을 폐기한다.
- 관리자 패스워드 변경, 등급 변경, 비활성화, OTP 초기화에 성공하면 대상 관리자의 활성 세션을 폐기하고 인증 버전을 증가시킨다.
- 인증 완료 세션의 절대 유효시간은 로그인 시점부터 최대 8시간이다.
- 인증 완료 세션의 유휴 만료시간은 마지막 활동 후 30분이다.
- 사전 세션은 서버가 정한 다음 단계로만 이동하며 보호된 관리자 기능의 권한을 갖지 않는다.
- 온보딩 사전 세션은 정식 자격 증명 설정, OTP 등록, OTP 검증 순서로만 전환한다.
- 세션 식별자와 CSRF 토큰 원문은 저장하지 않는다.
- 세션 유효성은 세션 상태와 현재 관리자 계정 상태를 함께 확인해 판단한다.
- 현재 관리자 계정 상태를 확인할 수 없으면 인증을 허용하지 않는다.
- 세션 인증 버전과 현재 관리자 인증 버전이 다르면 접근을 거부한다.

## 관리자 감사 로그(AdminAuditLog)

_Entity_

### 속성

- `id` : 감사 로그 식별자
- `actorAdminId` : 작업을 수행한 관리자 식별자
- `targetAdminId` : 작업 대상 관리자 식별자
- `action` : 작업 유형
- `reason` : 작업 사유
- `detail` : 변경 전후 값이나 보조 설명
- `occurredAt` : 감사 로그 발생 시각

### 규칙

- 감사 로그는 Admin 도메인이 소유한다.
- 감사 로그는 외부 기능을 통해 수정하거나 삭제할 수 없다.
- 비밀번호, OTP 비밀키, 세션 식별자, CSRF 토큰과 재설정 자격 증명 원문은 기록하지 않는다.
- 1차 범위에서는 성공한 관리자 운영 작업을 감사 로그로 기록한다.
- 등급 변경과 이메일 변경처럼 전후 값을 추적해야 하는 작업은 `detail`에 변경 전후 값을 기록한다.
- 별도 `success`, 요청 IP, User-Agent, 작업 당시 닉네임 스냅샷은 1차 감사 로그 모델에 포함하지 않는다.
- 감사 로그 조회는 `SUPER_ADMIN`만 수행할 수 있다.
- 감사 로그 CSV 내보내기는 1차 범위에서 제외한다.

## 관리자 통계 이벤트(AdminStatisticsEvent)

_Entity_

### 속성

- `eventType` : 통계 이벤트 유형
- `eventDate` : Asia/Seoul 기준 이벤트 날짜
- `occurredAt` : 이벤트 발생 시각
- `userId` : 이벤트와 연결된 일반 사용자 식별자
- `visitorKey` : 고유 방문자를 식별하기 위한 키

### 규칙

- 방문 수, 일일 고유 방문자 수, DAU, AI 사진 요청 수, AI 사진 실패 수는 관리자 통계 이벤트를 기반으로 계산한다.
- AI 사진 요청과 실패는 각각 독립된 통계 사건으로 기록한다.
- 통계 사건의 완전 전달 보장은 1차 범위에 포함하지 않는다.

## 관리자 일별 통계(AdminDailyStatistics)

_Entity_

### 속성

- `metricDate` : 집계 대상 날짜
- `dailyUniqueVisitors` : 일일 고유 방문자 수
- `totalVisits` : 전체 방문 횟수
- `dau` : 일일 활성 사용자 수
- `diaryCreations` : 성공적으로 저장된 일기 생성 수
- `aiPhotoRequests` : AI 사진 사용자 요청 수
- `aiPhotoSuccesses` : AI 사진 성공 수
- `aiPhotoFailures` : AI 사진 실패 수
- `signupMembers` : 일별 가입 회원 수
- `aggregatedAt` : 집계 시각

### 규칙

- 기본 조회 기간은 오늘을 포함한 최근 7일이다.
- 조회 기간은 최대 1년이다.
- 당일 데이터는 실시간으로 계산한다.
- 종료된 날짜는 확정된 일별 집계 결과를 우선 사용한다.
- 데이터가 없는 날짜는 0으로 표시한다.
- 모든 날짜 기준은 Asia/Seoul이다.
