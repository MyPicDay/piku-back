# Recommendation 도메인 모델

- Status: Active
- Audience: Engineers
- Source of Truth: Yes
- Last Reviewed: 2026-07-23

## 도메인 개요

Recommendation은 일기 본문에서 추천용 메타데이터를 만들고, 사용자의 주제별 상호작용을 친화도로 누적하며, 후보 일기에 개인화 점수를 부여하는 Supporting Context다.

### 목적

- 일기 본문을 주제 점수와 품질 점수로 분석한다.
- 피드 클릭 등 주제 상호작용을 사용자 친화도로 누적한다.
- 분석 메타데이터, 사용자 친화도와 최신성을 조합해 후보 점수를 계산한다.
- Diary와 Feed가 분석 저장 형식이나 Recommendation Entity를 직접 사용하지 않도록 공개 Application 계약을 제공한다.

## 경계와 소유권

- Recommendation은 `DiaryMetadata`, `UserPreference`, 주제 점수·친화도와 추천 점수 공식을 소유한다.
- Diary는 일기 내용과 생명주기를 소유하며 저장 커밋 이후 본문 분석을 요청한다.
- Feed는 후보 공개 범위, 친구 고정 슬롯, Cursor와 정렬 정책을 소유한다.
- Feed 클릭이 어느 일기에 발생했는지와 클릭 이력은 Feed가 소유하고, Recommendation은 전달받은 주제의 친화도 변화만 소유한다.
- JSON 저장 형식, JPA 변환, 시스템 시각과 로컬 키워드 분석 구현은 Adapter 책임이다.
- Recommendation에는 현재 Web API가 없으며 HTTP 오류와 OpenAPI 계약을 소유하지 않는다.

## DiaryMetadata

_Entity_

### 속성

- `diaryId`: 분석 대상 Diary 식별자이며 한 Diary에 하나만 존재한다.
- `primaryTopic`: 가장 높은 분석 점수의 대표 주제다.
- `topicScores`: 주제별 분석 점수 값 객체다.
- `qualityScore`: 본문 길이에 따른 현재 품질 점수다.
- `analyzedAt`: 마지막으로 분석 결과를 반영한 시각이다.

### 행위와 규칙

- 새 분석 결과를 기록하거나 기존 결과의 대표 주제, 주제 점수, 품질과 분석 시각을 함께 갱신한다.
- 분석 시각은 시스템 시각을 직접 읽지 않고 Application이 제공한다.
- 본문이 비어 있거나 어떤 키워드도 발견되지 않으면 대표 주제와 주제 점수는 `daily`, `{"daily": 1.0}`을 사용한다.
- 현재 품질 점수는 빈 본문 0.1, 20자 미만 0.2, 50자 미만 0.3, 100자 미만 0.5, 200자 미만 0.6, 300자 미만 0.7, 그 이상 0.9다.

## UserPreference

_Aggregate Root_

### 속성

- `userId`: 선호도 소유 사용자 식별자이며 사용자마다 하나만 존재한다.
- `topicAffinities`: 주제별 친화도 값 객체다.
- `lastUpdatedAt`: 마지막 상호작용을 반영한 시각이다.

### 상호작용 규칙

| 상호작용 | 친화도 증가량 |
| --- | ---: |
| LIKE | 0.30 |
| VIEW | 0.10 |
| CLICK | 0.15 |
| OTHER | 0.05 |

- 기존 친화도에 상호작용 증가량을 더한다.
- 한 주제의 친화도는 1.0을 넘지 않는다.
- 변경은 새 `TopicAffinities` 값으로 교체하며 외부에 변경 가능한 Map을 노출하지 않는다.
- 선호도 데이터가 없으면 빈 친화도로 시작한다.

## RecommendationScore

_Value Object / Domain Policy_

현재 후보 점수는 다음 값을 더해 계산한다.

- 대표 주제 친화도 × 0.4
- 품질 점수 × 0.3
- 최신성 점수 × 0.2

최신성 점수는 분석 시각을 기준으로 `1 / (1 + 경과 시간 / 72시간)`을 사용한다. 분석 시각이 없으면 생성 시각을 사용하고 두 시각이 모두 없으면 0.5를 사용한다.

- 대표 주제는 있지만 사용자 친화도가 없으면 주제 기본값 0.1을 사용한다.
- 대표 주제가 없으면 주제 점수는 0.0이다.
- 품질 점수가 없으면 0.5를 사용한다.
- 메타데이터가 없는 후보는 전체 기본 점수 0.3을 사용한다.
- 점수는 최대 1.0으로 제한한다.
- 같은 점수의 후보는 입력 순서를 유지한다.
- 친구 여부는 Recommendation 점수에 포함하지 않으며 Feed의 후보 구성 정책에서만 처리한다.

## 분석과 저장 실패

- Diary 생성·수정 커밋 이후 분석을 best-effort로 요청한다.
- 분석 기록은 독립 트랜잭션에서 수행하며 실패가 완료된 Diary 저장을 되돌리지 않는다.
- 분석 실패 시 기존 메타데이터가 있으면 그대로 유지한다.
- 기존 TEXT JSON 형식을 읽지 못하면 현재 호환 정책에 따라 빈 주제 값으로 복구하고 원문을 로그에 노출하지 않는다.
- 동시 상호작용의 유실 갱신 방지와 손상 데이터 운영 정책 강화는 별도 기능·동시성 계획에서 결정한다.

## 공개 Application 계약

- 일기 본문 분석 기록
- 일기 메타데이터 조회
- 클릭·좋아요·조회·기타 주제 상호작용 기록
- 사용자 주제 친화도 조회
- 후보 일기 점수 조회

공개 결과는 Recommendation Entity와 저장 JSON을 노출하지 않고 식별자, 대표 주제, 주제 점수, 품질과 계산 점수만 제공한다.
