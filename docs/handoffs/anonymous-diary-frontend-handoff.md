# Anonymous Diary Frontend Handoff

- Source of Truth: Yes
- Last Reviewed: 2026-06-08

## 목적

익명 일기 공개 타입 추가에 따라 프론트엔드와 모바일에서 변경해야 하는 응답 처리, 화면 표시, 액션 권한, 알림 처리 기준을 정의한다.

이 문서는 클라이언트 계약과 사용자 경험 변경점만 다룬다. 백엔드 내부 구현 순서나 저장소 구조는 다루지 않는다.

## 변경 요약

- 일기 공개 타입에 `ANONYMOUS`가 추가된다.
- 피드 일기 응답에 `isOwner`가 추가된다.
- 익명 일기에서 작성자 프로필 정보는 항상 익명으로 표시한다.
- 익명 일기에서 작성자 식별이 필요한 클라이언트 로직은 `userId` 대신 `isOwner`를 사용한다.
- 댓글 목록 응답에 `canReply`, `canEdit`, `canDelete`가 추가된다.
- 익명 일기의 댓글 작성자 정보는 모두 익명으로 표시하고, 원문을 볼 수 없는 댓글은 placeholder 문구로 표시한다.
- 익명 일기 알림은 발신자와 일기 작성자 식별값을 내려주지 않는다.
- 삭제된 일기와 연결된 알림은 알림 목록에서 내려오지 않는다.
- 사용자 프로필, 월별 일기 목록, 사용자 일기 사진 갤러리처럼 특정 사용자의 기록을 조회하는 화면에서는 익명 일기가 요청자 본인에게만 포함된다.

## 공개 타입 처리

클라이언트의 공개 타입 enum에 `ANONYMOUS`를 추가한다.

일기 작성과 수정 화면은 기존 공개 타입 선택지에 익명을 추가해야 한다. 익명 선택 시 사용자는 다음 결과를 기대해야 한다.

- 피드와 상세에서 작성자 닉네임은 `익명`으로 표시된다.
- 작성자 아바타는 표시하지 않는다.
- 작성자 프로필로 이동할 수 있는 진입점은 비활성화한다.
- 댓글 작성자도 모두 `익명`으로 표시된다.
- 일부 댓글 원문은 요청자 권한에 따라 `비공개 댓글` 또는 `비공개 답글`로 표시될 수 있다.

## 피드와 일기 상세

대상 화면은 피드 목록과 일기 상세이다.

대상 API는 `GET /api/diary`와 `GET /api/diary/{diaryId}`이다.

익명 일기 응답에서 클라이언트는 다음 규칙을 적용한다.

| 필드 | 익명 일기 처리 |
| --- | --- |
| `status` | `ANONYMOUS` 허용 |
| `nickname` | `익명`으로 표시 |
| `avatar` | 값이 없으므로 아바타 UI를 숨기거나 익명 기본 UI를 사용 |
| `userId` | 값이 없으므로 작성자 프로필 이동에 사용하지 않음 |
| `friendStatus` | `ANONYMOUS` 허용 |
| `isOwner` | 현재 사용자가 작성자인지 판단하는 기준 |
| `commentCount` | 전체 댓글 수로 표시 |
| `likeCount`, `isLiked` | 기존 좋아요 UI와 동일하게 사용 |

중요한 변경점은 익명 일기에서는 작성자 본인도 `userId`를 받지 않는다는 점이다. 기존처럼 응답의 `userId`와 로그인 사용자 ID를 비교해서 수정, 삭제, 작성자 메뉴 노출 여부를 판단하면 익명 일기 작성자에게도 작성자 액션이 보이지 않는다.

프론트는 일기 상세와 피드 목록에서 작성자 전용 액션을 `isOwner`로 판단해야 한다.

## 댓글 목록과 답글 목록

대상 API는 `GET /api/comments`와 `GET /api/comments/{parentCommentId}/replies`이다.

댓글 목록 응답에는 `canReply`, `canEdit`, `canDelete`가 추가된다. 클라이언트는 댓글 액션 노출 여부를 직접 계산하지 말고 이 값을 따른다.

| 필드 | 익명 일기 처리 |
| --- | --- |
| `userId` | 항상 값 없음 |
| `nickname` | 항상 `익명` |
| `avatar` | 항상 값 없음 |
| `content` | 볼 수 있으면 원문, 볼 수 없으면 placeholder |
| `replyCount` | 다른 사용자가 작성한 답글도 포함한 수로 표시 |
| `canReply` | 답글 입력 진입점 노출 기준 |
| `canEdit` | 수정 액션 노출 기준 |
| `canDelete` | 삭제 액션 노출 기준 |

익명 일기의 placeholder 문구는 서버 응답을 그대로 표시한다.

- 루트 댓글 원문을 볼 수 없는 경우: `비공개 댓글`
- 답글 원문을 볼 수 없는 경우: `비공개 답글`
- 볼 수 있는 삭제 댓글인 경우: `삭제된 댓글입니다.`

클라이언트는 익명 일기 댓글 목록에서 placeholder 행을 임의로 제거하지 않는다. 다른 사람이 작성한 댓글과 답글도 대화 존재를 표시하기 위해 목록에 남아야 한다.

익명 일기에서 댓글 권한은 다음 화면 규칙으로 처리한다.

- 비로그인 사용자는 댓글과 답글 원문을 볼 수 없고 액션도 없다.
- 일기 작성자는 모든 댓글과 답글 원문을 볼 수 있다.
- 댓글 작성자는 본인이 작성한 댓글과 답글 원문을 볼 수 있다.
- 루트 댓글 작성자는 본인 댓글에 일기 작성자가 작성한 답글 원문을 볼 수 있다.
- 원문을 볼 수 없는 댓글과 답글은 각각 placeholder 문구로 표시한다.
- 답글 입력 UI는 `canReply`가 true인 댓글에서만 노출한다.
- 수정과 삭제 UI는 각각 `canEdit`, `canDelete`가 true인 댓글에서만 노출한다.

댓글 수 표시는 전체 댓글 수 기준이다. 현재 사용자에게 원문이 보이는 댓글 수로 다시 계산하지 않는다.

## 알림 목록과 실시간 알림

대상 API는 `GET /api/sse/notifications`와 SSE 구독 이벤트이다.

익명 일기와 연결된 알림은 발신자 정보를 익명으로 표시한다.

| 필드 | 익명 일기 알림 처리 |
| --- | --- |
| `nickname` | `익명` |
| `avatarUrl` | 값 없음 |
| `diaryUserId` | 값 없음 |
| `relatedDiaryId` | 일기 상세 이동에 사용 가능 |
| `thumbnailUrl` | 대표 이미지 표시 가능 |

SSE 이벤트에서도 익명 일기 알림은 `senderId`가 없고, `senderNickname`은 `익명`, `senderAvatarUrl`은 값이 없다.

알림 목록에서 삭제된 일기와 연결된 알림은 내려오지 않는다. 클라이언트는 목록에서 별도 삭제 상태 알림 행을 만들 필요가 없다.

이미 기기에 남아 있는 로컬 푸시나 캐시된 알림을 통해 삭제된 일기 상세로 이동할 수는 있다. 이 경우 상세 API의 Problem Details 응답을 일반적인 접근 불가 또는 삭제된 콘텐츠 상태로 처리한다.

## 사용자 프로필, 월별 목록, 갤러리

대상 API는 사용자 프로필, 프로필 미리보기, 월별 일기 목록, 사용자 일기 사진 갤러리이다.

익명 일기는 특정 사용자의 기록 소유를 추정할 수 있는 화면에서 요청자 본인에게만 포함된다.

- 내 프로필, 내 월별 목록, 내 갤러리에서는 내 익명 일기가 포함될 수 있다.
- 다른 사용자의 프로필, 월별 목록, 갤러리에서는 그 사용자의 익명 일기가 포함되지 않는다.
- `diaryCount`와 `monthlyDiaryCount`는 현재 조회자에게 보이는 일기 기준으로 내려온다.
- 갤러리에서 `status`가 `ANONYMOUS`인 항목은 익명 공개 타입 배지나 상태 표시를 할 수 있다.
- 다른 사용자 화면에서 익명 일기 누락분을 클라이언트가 placeholder로 만들지 않는다.

## 화면별 변경 체크리스트

- 일기 작성 화면: 공개 타입 선택지에 익명 추가.
- 일기 수정 화면: 기존 익명 일기 수정 시 익명 타입을 선택 상태로 표시.
- 피드 목록: `ANONYMOUS` 상태, `ANONYMOUS` 친구 상태 허용.
- 일기 상세: 작성자 액션 판단을 `isOwner`로 변경.
- 작성자 프로필 링크: 익명 일기에서는 이동 비활성화.
- 댓글 목록: `canReply`, `canEdit`, `canDelete` 기반으로 액션 노출.
- 댓글 목록: `비공개 댓글`, `비공개 답글` 응답을 일반 텍스트로 표시.
- 답글 목록: 원문을 볼 수 없는 답글도 placeholder 행으로 표시.
- 알림 목록: 익명 알림에서 작성자 프로필 이동 비활성화.
- 알림 상세 이동: `relatedDiaryId`가 있으면 일기 상세 이동을 유지하되, 상세 접근 실패는 Problem Details 흐름으로 처리.
- 사용자 프로필, 월별 목록, 갤러리: 서버 응답에 없는 익명 일기 placeholder를 만들지 않음.

## 호환성과 QA 기준

프론트는 다음 시나리오를 확인해야 한다.

- 익명 일기 작성자가 상세에 들어가면 닉네임과 아바타는 익명 처리되고, 수정과 삭제 액션은 표시된다.
- 익명 일기 비작성자가 상세에 들어가면 작성자 프로필로 이동할 수 없다.
- 비로그인 사용자가 익명 일기의 댓글 목록을 보면 모든 원문이 placeholder로 보인다.
- 익명 일기 작성자는 댓글과 답글 원문을 모두 볼 수 있다.
- 댓글 작성자는 본인 댓글과 본인 답글만 원문으로 볼 수 있다.
- 루트 댓글 작성자는 그 댓글에 달린 일기 작성자의 답글 원문을 볼 수 있다.
- 다른 사용자의 댓글과 답글은 행이 사라지지 않고 placeholder로 표시된다.
- 댓글 수와 답글 수는 원문 열람 가능 여부와 관계없이 서버가 내려준 수를 표시한다.
- 익명 일기 알림은 발신자 닉네임이 `익명`이고 아바타와 일기 작성자 ID가 없다.
- 삭제된 일기 알림은 알림 목록 새로고침 후 표시되지 않는다.
- 다른 사용자의 갤러리와 월별 목록에는 그 사용자의 익명 일기가 표시되지 않는다.
