# 관리자 세션 인증 프론트엔드 Handoff

- Status: Active
- Audience: Backend Engineers, Frontend Engineers
- Source of Truth: Yes
- Last Reviewed: 2026-06-18

## 목적

관리자 프론트엔드가 액세스 토큰과 리프레시 토큰 없이 서버 세션 쿠키와 CSRF 토큰으로 관리자 API를 호출하기 위한 계약을 정의한다.

## 소비자 관점 변경점

- 관리자 API 요청은 브라우저 자격 증명 전송을 활성화한다.
- 관리자 액세스 토큰을 저장하거나 Authorization 헤더에 추가하지 않는다.
- 관리자 리프레시 토큰 쿠키와 토큰 재발급 요청을 제거한다.
- 화면 초기화 시 CSRF 초기화 API를 먼저 호출한다.
- GET, HEAD, OPTIONS를 제외한 관리자 요청은 CSRF 쿠키 값을 설정된 CSRF 요청 헤더에 전달한다.
- 관리자 세션 쿠키는 HttpOnly이므로 프론트엔드에서 읽거나 직접 조립하지 않는다.

## 인증 흐름

1. 관리자 화면 진입 시 CSRF 초기화 API를 호출한다.
2. 서버가 사전 세션 쿠키와 CSRF 쿠키를 발급한다.
3. 로그인 또는 임시 로그인 요청에 두 쿠키와 CSRF 요청 헤더를 함께 전송한다.
4. 온보딩과 OTP 단계는 같은 사전 세션을 사용하며 서버가 다음 단계를 검증한다.
5. OTP 성공 시 서버가 세션 쿠키와 CSRF 쿠키를 모두 새 값으로 교체한다.
6. 이후 보호 API는 교체된 쿠키와 CSRF 요청 헤더를 사용한다.
7. 로그아웃 시 서버가 세션을 폐기하고 두 쿠키를 만료시킨다.

## API 계약

| API | 인증 전 접근 | CSRF 및 Origin | 결과 |
| --- | --- | --- | --- |
| CSRF 초기화 | 허용 | 허용 Origin 필수, 기존 CSRF 불필요 | 사전 세션 및 CSRF 쿠키 발급 |
| 임시 로그인 | 허용 | 사전 세션, CSRF, Origin 필수 | 다음 온보딩 단계 반환 |
| 정식 로그인 | 허용 | 사전 세션, CSRF, Origin 필수 | OTP 검증 단계 반환 |
| 온보딩 단계 | 허용 | 사전 세션, CSRF, Origin 필수 | 서버가 허용한 다음 단계로만 이동 |
| OTP 검증 | 허용 | 사전 세션, CSRF, Origin 필수 | 인증 완료 상태와 관리자 요약 반환, 두 쿠키 교체 |
| 로그아웃 | 인증 필요 | 인증 세션, CSRF, Origin 필수 | 서버 세션 폐기 및 두 쿠키 만료 |
| 관리자 보호 API | 인증 필요 | 안전하지 않은 메서드는 CSRF와 Origin 필수 | 현재 계정 상태와 등급 기준으로 처리 |

로그인과 OTP 응답에는 액세스 토큰, 리프레시 토큰, 온보딩 토큰, OTP challenge token이 포함되지 않는다. 관리자 토큰 재발급 API는 존재하지 않는다.

## 쿠키와 헤더

- 쿠키와 CSRF 헤더의 실제 이름은 배포 환경 설정과 Swagger의 보안 스키마를 기준으로 공유한다.
- 세션 쿠키 경로는 관리자 API 범위이며 HttpOnly, Secure, SameSite Strict 정책을 사용한다.
- CSRF 쿠키는 프론트엔드가 읽을 수 있고 SameSite Strict 정책을 사용한다.
- 운영 CSRF 쿠키는 관리자 프론트엔드와 API가 공유하는 부모 도메인 범위다.
- 프론트엔드는 쿠키 이름에 의미를 부여하거나 이름을 고정값으로 소스에 복제하지 않는다.

## 오류 처리

관리자 인증, Origin, CSRF 실패는 RFC 9457 Problem Details 형식이다. 클라이언트는 문자열 본문이 아니라 status와 type을 기준으로 처리한다.

| 상황 | 상태 |
| --- | --- |
| 세션 없음, 만료, 폐기, 인증 버전 불일치 | 401 |
| Origin 또는 권한 거부 | 403 |
| CSRF 쿠키, 헤더, 서버 세션 불일치 | 403 |
| 계정 잠금 | 423 |
| OTP 일시 차단 | 429 |
| 관리자 세션 기준 저장소 확인 불가 | 503 |

401을 받으면 로컬 인증 상태를 초기화하고 CSRF 초기화부터 다시 시작한다. 403 CSRF 실패에서는 기존 요청을 자동 재전송하지 않고 새 사전 세션을 초기화한다.
