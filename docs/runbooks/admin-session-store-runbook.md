# 관리자 세션 저장소 장애 대응 Runbook

- Status: Active
- Audience: Backend Engineers, Operators
- Source of Truth: Yes
- Last Reviewed: 2026-06-18

## 목적

관리자 세션 Redis 캐시 장애, DB 기준 저장소 장애, 전체 관리자 세션 폐기가 필요할 때의 판단과 대응 절차를 정의한다.

## 기본 원칙

- DB의 관리자 세션이 인증 상태의 기준 원장이다.
- Redis는 관리자 세션 조회를 위한 보조 캐시이며 인증을 독립적으로 확정하지 않는다.
- Redis 장애 중에는 DB와 현재 관리자 계정 상태를 확인할 수 있는 요청을 계속 처리한다.
- DB 기준 저장소나 현재 관리자 계정 상태를 확인할 수 없으면 Redis 값만으로 요청을 허용하지 않는다.
- 세션 식별자, CSRF 토큰, 비밀번호, OTP 비밀키와 코드는 로그나 장애 기록에 남기지 않는다.

## 관측 신호

- Redis 캐시 적중은 `admin.session.cache.hit`, DB 폴백은 `admin.session.database.fallback`으로 확인한다.
- Redis 읽기, 쓰기, 삭제 실패는 `admin.session.cache.failure`의 `operation` 태그로 구분한다.
- DB 세션 조회 지연은 `admin.session.database.lookup`의 `operation` 태그로 확인한다.
- 현재 유효한 인증 완료 세션 수는 `admin.session.active`로 확인한다.
- DB 세션 또는 관리자 상태 확인 실패는 `admin.session.store.unavailable`로 확인한다.
- 로그인과 OTP 성공·거부는 `admin.authentication.login.*`, `admin.authentication.otp.*` 계열로 확인한다.
- CSRF와 Origin 거부는 `admin.security.csrf.rejected`, `admin.security.origin.rejected`로 확인한다.

## Redis 장애

### 판별

- 관리자 세션 캐시 오류와 DB 폴백 증가를 확인한다.
- DB 세션 조회 지연과 연결 풀 사용량이 함께 증가하는지 확인한다.
- 관리자 로그인과 보호 API가 DB 폴백으로 계속 처리되는지 확인한다.

### 대응

1. Redis 장애 범위가 관리자 세션 네임스페이스에 한정되는지 확인한다.
2. DB 부하와 관리자 API 지연이 허용 범위인지 확인한다.
3. DB 부하가 높으면 관리자 기능의 비필수 트래픽을 제한하고 로그인 실패 재시도를 억제한다.
4. Redis 복구 후 DB의 유효 세션이 요청 시점에 다시 캐시되는지 확인한다.
5. Redis에 남은 값을 DB로 역반영하지 않는다.

## DB 세션 저장소 장애

### 판별

- 관리자 인증 요청이 503 Problem Details로 종료되는지 확인한다.
- Redis 캐시가 남아 있어도 관리자 보호 요청이 성공하지 않는지 확인한다.
- 일반 사용자 JWT 인증과 다른 API가 같은 장애에 영향을 받는지 별도로 확인한다.

### 대응

1. 관리자 인증을 우회하거나 Redis 단독 인증을 활성화하지 않는다.
2. DB 연결, 관리자 세션 테이블, 관리자 계정 조회 상태를 확인한다.
3. 복구 전까지 관리자 프론트엔드에 재시도 간격과 장애 상태를 안내한다.
4. DB 복구 후 새 CSRF 초기화와 로그인을 통해 인증 흐름을 점검한다.
5. 장애 중 변경된 Redis 데이터를 기준 상태로 취급하지 않는다.

## 전체 관리자 세션 폐기

### 적용 상황

- 관리자 쿠키 이름 변경
- 관리자 인증 자격 증명 노출 의심
- 세션 검증 정책 결함
- 운영자가 모든 관리자 재로그인을 요구하는 보안 대응

### 절차

1. 폐기 대상과 사유, 적용 시각을 기록한다.
2. 관리자 계정 인증 버전을 증가시키고 활성 DB 세션을 폐기한다.
3. Redis 관리자 세션 네임스페이스를 제거한다.
4. 관리자 보호 요청이 401로 거부되는지 확인한다.
5. 새 CSRF 초기화와 로그인 후 하나의 활성 세션만 생성되는지 확인한다.
6. 세션 또는 CSRF 원문이 로그와 운영 기록에 포함되지 않았는지 확인한다.

## 복구 완료 기준

- Redis 장애에서는 DB 폴백 인증과 점진적 캐시 재적재가 확인된다.
- DB 장애에서는 복구 전 요청이 503으로 fail-closed 처리된다.
- 전체 폐기에서는 기존 세션이 모두 거부되고 새 로그인만 허용된다.
- 관리자 계정 상태와 등급 변경이 다음 요청에 반영된다.
